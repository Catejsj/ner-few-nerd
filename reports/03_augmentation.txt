[1] WHY AUGMENT AT ALL
    Base file: train_small, 20,000 sentences, 51,755 entities.
    The full training split has 131,767 sentences, but the CRF is fitted
    on a subsample for memory reasons, so from the CRF's point of view
    this IS a limited-data setting - which is the condition the rubric
    asks augmentation to be justified by.

    entity counts in the base file
      location        14,731
      person          11,466
      organization     9,846
      other            5,226
      product          3,424
      building         2,702  <- targeted
      art              2,197  <- targeted
      event            2,163  <- targeted

    Targeting the 3 rarest types: art, building, event.

[2] WHY MENTION REPLACEMENT AND NOT THE OTHER METHODS
    random deletion   shifts every label after the deleted token
    random insertion  can land inside an entity and corrupt its span
    back-translation  returns different token boundaries with no way to
                      map the old labels onto the new tokens
    mention replacement  keeps the sentence and swaps one entity for
                      another of the same type; the labels are rebuilt
                      around the new length, so they stay correct.
    Reference: Dai and Adel (2020), 'An Analysis of Simple Data
    Augmentation for Named Entity Recognition'.

    sentences  20,000 -> 29,410 (+9,410 augmented)

    Note the non-targeted types grow too. An augmented sentence keeps its
    other entities, so a sentence containing both an art entity and a
    person contributes that person again. The targeted types still grow
    fastest, which is the point.

[6] THE HONEST WARNING
    Mention replacement produces sentences that are often factually
    absurd - a director being released as a film, a war fought in a
    museum. That is acceptable for a CRF, which learns from surface
    patterns and context words, not from world knowledge. It would NOT be
    acceptable if we were fine-tuning a language model, which can be
    damaged by implausible text.

    Whether it actually helped is an empirical question, answered by
    rerunning the CRF on this file:
      ./.venv/bin/python scripts/approach_crf.py --train-file train_small_aug
    and comparing reports/04_crf.txt before and after. The comparison is
    recorded in reports/07_augmentation_effect.txt.
